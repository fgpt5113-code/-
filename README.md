# Phone UX Logger

Локальный диагностический логгер Android для анализа повседневного взаимодействия с телефоном **без root**.

## Что он пишет

В обычном режиме Accessibility-сервис фиксирует:

- время события;
- пакет и класс активного интерфейса;
- клики, долгие клики, фокус, выбор, изменение текста **без самого текста**;
- прокрутки и их системные параметры;
- смену окон;
- начало/конец touch interaction, если Android генерирует эти события;
- аппаратные `KeyEvent` как код клавиши, без Unicode/введённой строки;
- границы `AccessibilityNodeInfo` и для событий с доступным source — приблизительную точку `X/Y` как центр этих границ;
- включение/выключение/разблокировку экрана и снимок уровня/температуры батареи в эти моменты.

Никакие сетевые разрешения не запрашиваются. В `AndroidManifest.xml` намеренно отсутствует `INTERNET`.

## Главное ограничение без root

Обычное Android-приложение не может пассивно копировать **все сырые** touchscreen `MotionEvent` и одновременно оставлять их доставку приложениям неизменной.

На Android 14 / API 34 метод `AccessibilityService.onMotionEvent()` позволяет запросить события touchscreen, но выбранный источник ввода в это время не передаётся остальной системе. Поэтому в приложении есть отдельный **10-секундный тест сырых координат**. Во время него интерфейс временно не реагирует на касания; затем режим автоматически отключается.

Для обычного непрерывного наблюдения `x_px/y_px` — это центр bounds элемента, вызвавшего Accessibility-событие. Это не утверждается как физическая координата касания.

## Что намеренно НЕ сохраняется

- `event.getText()`;
- текст `AccessibilityNodeInfo`;
- `beforeText`;
- `contentDescription`;
- содержимое уведомлений;
- пароли;
- скриншоты/запись экрана;
- сетевой трафик.

`isPassword` сохраняется только как булев флаг в metadata, чтобы видеть, что событие относилось к парольному полю, не читая его содержимое.

## Сборка

Проект сделан без AndroidX и без сторонних библиотек.

1. Открой папку `PhoneUXLogger` в Android Studio.
2. Дождись Gradle Sync. Конфигурация: `compileSdk 35`, `minSdk 26`, `targetSdk 35`, Java 17.
3. `Build -> Build APK(s)`.
4. Установи APK на телефон.
5. Запусти `Phone UX Logger` и нажми **«Открыть настройки спец. возможностей»**.
6. Включи сервис **Phone UX Logger**.

Если Android Studio предлагает обновить Android Gradle Plugin/Gradle, можно принять совместимую миграцию — код использует только стандартные Android API.

## Использование

По умолчанию включён умеренный набор событий. Флажок **«Полный поток Accessibility-событий»** разрешает записывать все типы событий, которые передаёт Android; журнал при этом может быстро расти.

Через несколько часов/дней открой приложение и экспортируй журнал в **CSV** или **JSON**. Экспорт идёт через системный Storage Access Framework — приложение само не требует широкого доступа к файлам.

После экспорта файл можно передать на анализ. Полезные поля:

- `ts` — Unix time в миллисекундах;
- `kind` — `accessibility`, `key`, `raw_touch`, `system`, `service`;
- `event_name` — тип события;
- `package_name`, `class_name`, `view_id`;
- `left_px/top_px/right_px/bottom_px`;
- `x_px/y_px`;
- параметры scroll;
- `meta` — минимальные технические признаки без содержимого текста.

## Известные ограничения

Некоторые приложения и защищённые интерфейсы могут не отдавать source/идентификаторы/часть Accessibility-данных. Android также может ограничить фоновые процессы производителя телефона. Если сервис самопроизвольно выгружается, для него может понадобиться отключить оптимизацию батареи в настройках конкретной прошивки.

Сырые координаты на Android 13 и ниже этим проектом не записываются. Использовать Touch Exploration как постоянный обходной путь я намеренно не стал: он меняет обычную семантику управления телефоном.
